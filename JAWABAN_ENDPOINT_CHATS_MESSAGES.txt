JAWABAN PERTANYAAN 1: ENDPOINT GET ALL CHATS
==========================================================================

STATUS: ❌ ENDPOINT INI BELUM ADA - PERLU DIBUAT BARU

Endpoint yang AKAN DIBUAT:
GET /api/v1/sessions/{sessionId}/chats

Kenapa belum ada?
- Baileys library (WhatsApp Web JS) tidak menyimpan chats di database secara default
- Chats hanya ada di memory selama socket aktif
- Perlu implement custom logic untuk fetch chats dari WhatsApp

Solusi yang akan saya implement:
1. Buat endpoint baru: GET /sessions/{sessionId}/chats
2. Endpoint ini akan call Baileys method untuk fetch chats
3. Return list chats dengan format yang user butuhkan


ENDPOINT BARU YANG AKAN DIBUAT:

Method: GET
URL: http://72.62.125.132/api/v1/sessions/{sessionId}/chats
Headers:
  X-API-Key: wapi_35a798b44e8fed9075487b003bb8df8197ffb69d3805f17a379d26495de43af3

Query Parameters:
- limit (optional, default: 50): Jumlah maksimal chats
- filter (optional): 'unread', 'groups', 'personal'
- search (optional): Cari nama kontak

Contoh Request:
```bash
# Get semua chats
curl -X GET "http://72.62.125.132/api/v1/sessions/266cdcce-97a1-4d70-a6c5-b561b90acdfd_1768202501412/chats" \
  -H "X-API-Key: wapi_35a798b44e8fed9075487b003bb8df8197ffb69d3805f17a379d26495de43af3"

# Get chats dengan filter
curl -X GET "http://72.62.125.132/api/v1/sessions/266cdcce-97a1-4d70-a6c5-b561b90acdfd_1768202501412/chats?filter=unread&limit=20" \
```

JAWABAN PERTANYAAN 3: ENDPOINT GET MESSAGES DARI SPECIFIC CHAT
==========================================================================

STATUS: ❌ ENDPOINT INI BELUM ADA DALAM FORMAT INI

Endpoint yang ADA saat ini:
GET /api/v1/messages/{sessionId}/messages
→ Ini get messages dari DATABASE (yang sudah disimpan via webhook)

Endpoint BARU yang AKAN DIBUAT:
GET /api/v1/sessions/{sessionId}/chats/{chatId}/messages
→ Ini akan fetch messages LANGSUNG dari WhatsApp (Baileys)

PERBEDAAN:
1. Endpoint lama (/messages/{sessionId}/messages):
   - Ambil dari database MySQL
   - Hanya messages yang sudah pernah diterima/dikirim
   - Fast karena dari DB
   - Good untuk history

2. Endpoint baru (/sessions/{sessionId}/chats/{chatId}/messages):
   - Ambil langsung dari WhatsApp via Baileys
   - Semua messages termasuk yang belum pernah di-sync
   - Lebih lambat karena fetch dari WA server
   - Good untuk full sync pertama kali

WEBHOOK HEADERS:
```
POST https://8a5fa0c560ec.ngrok-free.app/api/webhook/whatsapp
Content-Type: application/json
X-Webhook-Signature: sha256=1a2b3c4d5e6f...
User-Agent: WhatsApp-API-Webhook/1.0
```

X-Webhook-Signature adalah HMAC SHA256 dari payload menggunakan webhook_secret.


VERIFY WEBHOOK SIGNATURE (PHP):
```php
$payload = file_get_contents('php://input');
$receivedSignature = $_SERVER['HTTP_X_WEBHOOK_SIGNATURE'];
$webhookSecret = 'your-webhook-secret'; // dari database

$expectedSignature = 'sha256=' . hash_hmac('sha256', $payload, $webhookSecret);

if (!hash_equals($expectedSignature, $receivedSignature)) {
    http_response_code(401);
    die('Invalid signature');
}

$data = json_decode($payload, true);
// Process webhook...
```

JAWABAN PERTANYAAN 7: RATE LIMITING
==========================================================================

STATUS: ⚠️ BELUM ADA RATE LIMITING YANG STRICT

Saat ini belum ada rate limiting yang ketat. Namun rekomendasi:

RECOMMENDED LIMITS (akan diimplement):
- GET /sessions/{sessionId}/chats: 60 requests/minute
- GET /sessions/{sessionId}/chats/{chatId}/messages: 30 requests/minute
- POST /messages/{sessionId}/send/*: 20 requests/minute
- Global API: 300 requests/minute per API Key

WHATSAPP SERVER LIMITS (dari WhatsApp):
- Kirim pesan: ~20-30 pesan/menit (soft limit)
- Fetch messages: Unlimited, tapi throttle di 50 requests/menit
- Jika over limit: WhatsApp akan temporer block socket (30-60 menit)

BEST PRACTICES:
1. Jangan fetch messages terlalu sering (max 1x per 5 detik)
2. Gunakan webhook untuk realtime updates (jangan polling)
3. Batch operations jika kirim banyak pesan
4. Implement exponential backoff untuk retry

RESPONSE WHEN RATE LIMITED:
```json
{
  "success": false,
  "error": {
    "code": "RATE_LIMIT_EXCEEDED",
    "message": "Too many requests. Please try again in 60 seconds.",
    "statusCode": 429,
    "retryAfter": 60
  }
}
```

HTTP Status: 429 Too Many Requests
Header: Retry-After: 60
